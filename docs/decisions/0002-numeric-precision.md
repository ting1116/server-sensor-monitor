# 0002 溫度數值精度：以 double 比較，限制輸入小數位數

- 狀態：Accepted
- 日期：2026-10-01

## 問題

v0.1 同時要求「溫度以 double 處理」和「比較前不得四捨五入」。但把十進位字串轉成 double 這個動作本身就是一次四捨五入。例如 `84.99999999999999999` 經 `strtod` 轉換後恰好等於 `85.0`，會被判為 WARNING，但數學上它小於 85，應判為 OK。

## 考慮的方案

| 方案 | 做法 | 評估 |
|---|---|---|
| (a) 採用 double 並限制輸入 | 溫度最多 6 位小數，profile 溫度欄位為整數且絕對值 ≤ 1e6 | 實作簡單；可以證明結果與十進位數學一致 |
| (b) 十進位字串比較 | 用字串或定點整數比較，不經過浮點 | 精確，但 parser 和 evaluator 都會變複雜，不符合 v1.0「小而完整」的目標 |

## 決策

採用方案 (a)。

## 為什麼 (a) 是正確的

設 x 為輸入的十進位值（最多 6 位小數），t 為 profile 的整數門檻（|t| ≤ 1e6），fl(·) 為 IEEE 754 binary64 的 round-to-nearest 轉換。

1. fl 是單調函數：x < t ⇒ fl(x) ≤ fl(t)。所以只需排除「x ≠ t 但 fl(x) = fl(t)」的情況。
2. x ≠ t 時 |x − t| ≥ 1e-6。
3. 當 |x| < 2^30（約 1.07e9）時，相鄰 double 的間距 ≤ 2^30 × 2^-52 ≈ 2.4e-7，小於 1e-6 / 2，因此 fl(x) ≠ fl(t)。整數 t 本身可以被 double 精確表示。
4. 當 |x| ≥ 2^30 時，因為 |t| ≤ 1e6，x 和 t 相差極大，比較結果不會改變。

因此，對所有語法合法的輸入，`fl(x) >= fl(t)` 與 `x >= t` 結果相同。

## 影響

- 規格 5.1：溫度語法改為 `-?[0-9]+(\.[0-9]{1,6})?`。
- 規格 6：profile 數值欄位必須是 JSON integer，絕對值 ≤ 1,000,000。
- 規格 7.1：text 模式直接顯示原始字串，不經 double 轉回字串。
- 新增 TC-29（6 位與 7 位小數的邊界案例）。
- 日後若要允許小數門檻，必須重新檢查第 3 點的推論，並更新本決策。
